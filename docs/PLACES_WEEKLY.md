# 플레이스 탐색: 이번 주 뭐가 뜰까?

## 앱과 기존 API 기준

2026-10-26 RN의 `src/components/place/PlaceWeeklySection.tsx`, `PlaceWeeklyPopupList.tsx`, `src/lib/popups.ts`와 기존 백엔드의 `PublicPopupController.browse`, `PublicPopupService.browse`, `PublicPopupMapper.browseQuery`를 읽기 전용으로 확인했다.

- 월요일~일요일 중 운영 기간이 하루라도 겹치는 팝업이다. **그 주 신규 오픈만을 뜻하지 않는다.**
- 실제 조건은 `startDate <= weekEnd AND endDate >= weekStart`다.
- 기존 공개 팝업 API의 주간 모드 `GET /api/popups?weekStart=YYYY-MM-DD&weekEnd=YYYY-MM-DD&languageCode=ko`를 그대로 사용한다. 웹에서는 국가를 지정하지 않아 한국·일본을 함께 표시한다.
- 정렬은 시작일 오름차순, 같은 시작일은 기존 서버 ID 오름차순이다. 최대 9개를 선택하는 별도 모드이며 `limit`·`cursor`를 보내지 않는다. 응답은 `popups`, `nextCursor:null`이다.
- 이전 주 결과에는 현재 종료된 팝업도 포함한다. 앱처럼 현재 날짜 기준 진행 중·오픈 예정·종료를 구분하며 임의로 종료된 항목을 삭제하거나 진행 중으로 표시하지 않는다.
- 앱의 주간 선택에는 별도 과거·미래 이동 제한이 없다. 웹도 선택 주의 이전/다음 주로 계속 이동하며 선택 주를 중앙에 표시한다.
- 앱의 4분 주간 캐시와 별개로 웹은 기존 웹 공개 조회 정책과 같은 Nitro 30초 캐시를 사용한다.

## 구현

`PlacesWeekly.vue`를 지역 탐색 바로 아래에 추가했다. 앞선 탐색 컴포넌트와 전체 탭·홈·지도·상세 페이지는 변경하지 않는다.

- PC 1120px 이상: 3열, 최대 3행, 간격 16px.
- 태블릿 768px 이상: 2열, 간격 16px.
- 모바일: 한 페이지 3개를 세로로 배치하고 최대 3페이지, Embla 스와이프와 인디케이터 제공. 무한 반복 없음.
- 포스터 104×140px, radius 8px, 제목 15px/600/한 줄 말줄임, 지역·기간 13px 회색. 태그·상태는 기존 웹 의미 색상 토큰을 재사용한다.
- 선택 주의 테두리·글자·점은 `#7839EF`, 비선택은 기존 연한 회색이다.
- 하트는 현재 웹과 동일한 24px, stroke 2, 흰색 테두리, `#6B7280` 채움, 원형 배경 없는 준비 중 비활성 상태다.
- 실제 `publicId`로 기존 `/places/{publicId}` 상세 링크를 구성한다.
- 실제 배열만 렌더링하며 빈 카드·중복 카드를 추가하지 않는다. 0개 안내와 로딩·오류·재시도를 구분한다.

## SSR·날짜·요청

- 최초 기준 날짜는 UTC+9의 날짜 문자열을 Nuxt `useState` payload에 넣고 서버와 클라이언트가 공유한다. 주 시작 계산은 해당 날짜의 UTC 날짜 연산으로 수행해 브라우저 시간대·DST 영향과 Hydration 날짜 차이를 피한다.
- `useFetch`의 주간별 키와 SSR payload를 사용해 초기 HTML에 실제 카드 9개와 날짜 선택을 포함한다. 초기 Hydration 추가 조회는 없다.
- Nuxt 중계 `GET /api/places/weekly?weekStart=...`는 월요일 시작을 검증하고 일요일을 계산해 기존 백엔드 API에 전달한다. 새로운 Spring API는 만들지 않는다.
- 쿼리는 `weekStart`만 허용한다. 임의 URL·커서·페이지 크기·인증 정보는 전달하지 않는다.
- Nitro 캐시는 API Base URL·선택 주·UTC+9 기준 날짜별 30초이며 SWR 없음이다. 브라우저 API 응답은 no-store다.
- 캐시 미적중 시 초기 1회, 선택 주 변경당 1회 조회한다. 카드별 추가 조회, 모바일 페이지 변경에 따른 API 호출은 없다.
- 기존 섹션과 동일하게 활성 탭에서 데이터가 3분 이상 오래됐거나 날짜가 바뀐 경우 갱신한다. 만료된 이미지 복구는 오래된 응답에 한해 제한적으로 수행한다. 무조건적인 초기 재조회는 하지 않는다.
- 주간 변경 요청은 `dedupe:cancel`을 사용한다. 선택한 주와 응답의 `weekStart`가 같은 경우만 표시해 늦은 이전 응답이 새 결과를 덮지 않게 한다.
- 응답의 운영 기간·이미지 URL·주간 모드·개수를 검증하고 publicId로 중복 제거한다. API 형식 오류를 빈 결과로 취급하지 않는다.

## 실제 조회 및 검증 결과

2026-10-26 공개 API의 실제 결과:

| 선택 주 | 조회 개수 | nextCursor | 현재 종료 상태 |
| --- | ---: | --- | ---: |
| 10.19 - 10.25 | 9 | null | 3 |
| 10.26 - 11.1 | 9 | null | 0 |
| 11.2 - 11.8 | 9 | null | 0 |

이 숫자는 당시 조회 기록이며 제품 코드에 고정하지 않는다. 최대 9개 선정 결과로, 해당 주 전체 팝업 총개수라는 의미가 아니다.

- `npm run typecheck`, `npm run build` 통과.
- 실제 3개 주 응답의 날짜 겹침·정렬·과거 종료 상태를 확인했다.
- 월/일 경계, 연말, 윤년, UTC+9 자정, 중복 제거, 잘못된 날짜·이미지·페이지 모드 및 빈 응답을 검증했다.
- 실제 응답을 재생하는 Nitro SSR에서 실제 카드 9개를 초기 HTML에 표시했고 초기 주간 백엔드 조회 1회, Hydration 중복 요청 0회를 확인했다.
- 같은 응답으로 비표시 Chrome에서 PC 3×3(826px 콘텐츠·264.66px 카드), 태블릿 2열, 모바일 3개 단위 스와이프·인디케이터·마지막 경계, 104×140 포스터, 하트와 실제 상세 링크를 확인했다.
- 주간 변경 후 첫 페이지 복귀, 지연된 이전 응답이 선택 주를 덮지 않음, 캐시 재사용을 확인했다.
- 빈 주와 실패 응답은 별도 검증용 계약 응답으로 구분 검증했다. 이 응답은 제품 코드에 포함하지 않았다.
- 최종 Hydration mismatch·미처리 예외·가로 넘침 없음. 외부 포스터 다운로드나 스크린샷 촬영은 하지 않았다.

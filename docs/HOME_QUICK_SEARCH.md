# 홈 메인 빠른 검색

## 사용한 기존 계약

2026-10-26 RN `src/lib/popups.ts`의 `searchPopups`와 `PopupSearchResult`, 백엔드 `PublicPopupController.search`, `PublicPopupMapper.search`, `PopupTranslationMapper.search`를 읽기 전용으로 확인했다.

- 기존 백엔드: `GET /api/popups/search?q=...&limit=5&languageCode=ko|ja`.
- 검색어는 앞뒤 공백 제거 후 Unicode 코드 포인트 기준 2~100자다. 기존 API의 limit 범위는 1~10이며 홈에서는 5로 고정한다.
- 응답은 `{ popups: [{ id, name, latitude, longitude, address, regionName }] }`다. `regionName`은 null일 수 있다. 포스터·전체 개수·커서는 없다.
- `id`는 공개 팝업 ID다. 실제 검색 결과 한 건을 기존 상세 API에서 확인해 `publicId`와 일치함을 검증했다. 웹의 기존 상세 경로 `/places/{id}`를 사용한다.
- 기존 API처럼 이름을 검색하며 좌표가 없는 팝업은 제외된다. 검색어가 포함된 이름을 조회하고 기존 서버의 일치도·날짜 정렬을 유지한다. 주소·지역 검색 또는 전체 검색 결과 목록으로 확장하지 않는다.
- 일본어 가나·한자가 있고 한글이 없는 입력은 `languageCode=ja`, 그 외는 `ko`로 조회한다. 번역 이름을 검색하는 기존 API 특성에 맞추며 두 언어를 동시에 호출하지 않는다.

## 수정 범위

기존 `app/pages/index.vue`의 중앙 검색 form과 해당 CSS만 `HomeQuickSearch.vue`로 분리해 연결했다. 높이 48px, 데스크톱 너비 826px, 기존 입력 스타일·문구·퍼플 버튼은 유지한다. 다른 홈 섹션과 상단 헤더 검색 버튼·플레이스·지도·상세 디자인은 수정하지 않는다.

드롭다운은 form 기준 절대 배치로 콘텐츠를 밀지 않으며 form과 같은 너비, 흰 배경·12px radius·보더·약한 그림자를 사용한다. 이름과 주소는 각 한 줄로 말줄임하고, 이름의 첫 일치 부분을 안전한 텍스트 렌더링으로 강조한다. 포스터를 추가 조회하지 않는다.

## 요청·상태·접근성

- 사용자 입력 후에만 실행한다. 초기 SSR·Hydration에서 검색 요청은 0회다.
- 300ms 디바운스, 2자 미만·공백·100자 초과·IME 조합 중 요청 없음.
- 동일한 정규화 검색어는 변경으로 취급하지 않는다. 성공 응답은 언어+검색어별로 컴포넌트 생명주기 동안 최대 20개를 재사용한다. 빈 성공 결과도 캐시한다.
- 입력 변경·닫기·언마운트 시 이전 타이머와 요청을 취소한다. 요청 세대·현재 검색어를 함께 확인해 늦은 응답의 표시를 막는다.
- 자동 재시도·주기적 갱신 없음. 닫았다 다시 열면 보유 결과나 오류를 표시하며, 취소된 미완료 검색은 새 디바운스 후 조회할 수 있다.
- Enter와 퍼플 버튼은 같은 submit 함수를 사용한다. 선택된 결과가 있을 때만 상세로 이동하고, 선택하지 않았으면 결과만 열며 첫 항목으로 이동하지 않는다.
- ArrowDown/ArrowUp은 활성 결과를 이동하고 Escape는 검색어를 유지한 채 닫는다. 바깥 클릭·검색어 삭제로 닫고 다시 클릭하면 유효한 검색어의 기존 상태를 연다.
- 결과 링크의 Nuxt prefetch를 꺼 항목마다 상세 요청이 발생하지 않게 한다. 실제 클릭·선택 후 이동에 필요한 기존 상세 조회만 수행한다.
- input의 combobox·label·aria-expanded·aria-controls·aria-activedescendant, listbox·option·aria-selected와 포커스 표시를 제공한다. IME 확정 Enter를 상세 이동으로 해석하지 않는다.
- 로딩, 결과, `검색 결과가 없어요.`, `검색 중 문제가 발생했어요.`를 구분한다. 오류를 0개 결과로 바꾸지 않는다.

## Nuxt 중계 및 캐시

새 Spring API 없이 Nuxt의 정적 경로 `server/api/popups/search.get.ts`를 추가했다. 동적 `[id]` 상세 경로와 구분된다.

- 클라이언트는 `/api/popups/search`에 `q`, `languageCode`만 전달한다. 중계에서 limit=5를 고정한다.
- 허용 쿼리·검색어 길이·언어 및 응답 필드·좌표·ID를 검증한다. 검색 결과는 ID로 중복 제거하며 서버 순서를 유지한다.
- 기존 Nitro 공개 조회 패턴대로 API Base URL·검색어·언어별 30초 캐시, SWR 없음이다. 브라우저 응답은 no-store다.
- 고정된 기존 공개 백엔드 경로만 호출하며 Cookie·Authorization을 전달하지 않는다. API Base URL은 서버 runtimeConfig에 유지한다.
- 캐시 미적중 시 유효한 새 검색어당 백엔드 1회다. 결과별 추가 요청은 0회다.

## 완료 검증

- `npm run typecheck`, `npm run build` 통과. 구현 후 통과한 결과를 유지했으며 작업 재개 후 중복 실행하지 않았다.
- 실제 공개 검색 API를 4회 호출해 한국어 5개, 한국어 모드의 일본어 입력 0개, 없는 검색어 0개, 일본어 모드의 일본어 입력 5개를 확인했다. 상세 ID 대조는 별도 공개 상세 요청 1회였다.
- 실제 응답을 재생한 Nitro SSR·비표시 Chrome에서 초기 SSR/Hydration 검색 요청 0회, 300ms 디바운스, 앞뒤 공백 제거, 1글자·공백·IME 중 요청 없음, 최대 5개, 성공 결과 재사용을 확인했다.
- 클릭과 ArrowDown/Up·Enter로 실제 검색 publicId의 기존 상세 페이지가 열리는 것을 확인했다. 선택 없는 Enter·버튼은 홈에 머물렀다.
- Escape·바깥 클릭·다시 열기·삭제, 오류와 빈 결과 구분, 자동 재시도 없음, 늦은 응답이 최신 결과를 덮지 않음을 확인했다. 오류·지연 응답은 검증용 계약 조건이며 제품 목업 데이터가 아니다.
- 전체 동작 검증의 검색 요청은 브라우저 7회·재생 백엔드 6회였다. 컴포넌트 재마운트 후 동일 검색의 브라우저 요청은 서버 캐시로 처리됐다. 항목 선택 전 상세 요청은 0회였다.
- 기존 검색창은 826×48px, 모바일도 48px 높이·드롭다운 동일 너비를 유지했다. 아래 콘텐츠 위치 변화와 가로 넘침이 없었다. TODAY와의 간격은 별도 집중 검증에서 24px이었다.
- 최종 Hydration mismatch·미처리 예외 없음. 스크린샷 촬영이나 외부 이미지 다운로드는 하지 않았다.

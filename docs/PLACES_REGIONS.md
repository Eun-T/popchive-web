# 플레이스 전체 API 연결 및 지역 탐색

## 범위와 현재 상태

2026-10-26 사용자가 전체 탭의 실제 API·지역 ID 연결까지 범위를 확장했다. 기존 전체 탭의 18개 목업 카드 및 문자열 지역·카테고리 키를 실제 공개 팝업 API로 교체했다. 기존 카드 디자인·비활성 하트·조건 설정 시트는 유지한다.

탐색 탭은 곧 끝나요 → 여기서 열리는 팝업 → 어디로 놀러 갈까? 순서다. 앞 두 컴포넌트, 홈·지도·상세 페이지와 백엔드·DB는 수정하지 않는다.

지역 탐색의 필터·반응형·국가 페이지는 구현했으며 **지역 사진은 권리 증거 미확인으로 반입 보류**다. 현재 카드에는 사진 없이 지역명과 배경만 표시한다. 자세한 파일 목록은 [이미지 반입 기록](../public/images/regions/README.md)을 참고한다.

## 기존 API와 실제 검증 결과

앱 `src/constants/placeRegionMocks.ts`, `src/components/place/PlaceRegionSection.tsx`, `src/locales/filterLabels.ts` 및 `PlaceScreen.tsx`를 읽기 전용으로 확인했다. 아래 순서와 숫자 ID는 실제 `/api/regions?countryCode=KR|JP` 응답과 일치했다.

| 페이지 | 순서 | 지역 | ID | 현재 목록 결과 |
| --- | --- | --- | --- | --- |
| 한국 | 1 | 성수 | 1 | 6 |
| 한국 | 2 | 홍대·신촌 | 4 | 3 |
| 한국 | 3 | 여의도 | 2 | 2 |
| 한국 | 4 | 강남·서초 | 5 | 3 |
| 일본 | 1 | 도쿄 | 15 | 1 |
| 일본 | 2 | 오사카 | 16 | 1 |
| 일본 | 3 | 교토 | 17 | 0 |
| 일본 | 4 | 나고야 | 18 | 0 |

각 결과는 `GET /api/popups?limit=10&languageCode=ko&countryCode=...&regionIds=...`의 당시 응답이다. 8개 모두 `nextCursor=null`이었다. 화면 지역 카드에 개수는 표시하지 않으며 이 숫자를 코드에 넣지 않는다.

국가 미선택 기본 전체 목록은 당시 10+10+2, 3페이지·고유 팝업 22개였다. 기본 목록은 기존 API처럼 종료된 팝업을 제외한다. 종료 상태를 명시적으로 선택하면 종료된 팝업도 조회한다. 이는 홈 전체 통계와 별개의 페이지네이션 API 계약이다.

백엔드 `PublicPopupController.browse`, `PublicPopupService.browse`, `PublicPopupMapper.xml`을 확인했다.

- `limit=10`, `nextCursor` 방식이다. 배열 길이를 전체 개수라고 표시하지 않는다.
- 정렬은 기존 API의 `created_at DESC, id DESC` 최신 등록순이다. 임의 정렬 파라미터를 만들지 않는다.
- `countryCode`, `regionIds`(쉼표 구분), `tagIds`(쉼표 구분), `status`를 서버에 전달한다.
- 여러 지역·여러 태그는 각각 OR, 서로 다른 필터 그룹은 AND다.
- 응답의 `publicId`, `name`, `countryCode`, `regionId`, `startDate`, `endDate`, `coverImageUrl`, `tags`를 사용한다. 표시 날짜는 날짜 문자열 그대로이며 진행 조건과 캐시 날짜는 한국·일본 공통 UTC+9다.

## 데이터 흐름·요청·캐시

Nuxt의 읽기 전용 중계 경로만 추가했다. Spring의 새 API는 만들지 않았다.

| 웹 중계 | 기존 백엔드 | 캐시 미적중 시 요청 |
| --- | --- | --- |
| `/api/places/options` | `/api/regions?countryCode=KR`, `JP`, `/api/tags` | 3회 |
| `/api/places/popups` | `/api/popups?limit=10&languageCode=ko` 및 필터·커서 | 페이지당 1회 |

- 옵션은 API Base URL별 300초, 목록은 Base URL·필터·커서·UTC+9 날짜별 30초 캐시다. 기존 홈과 동일한 Nitro 공개 응답 캐시 방식을 사용하며 SWR은 없다.
- 초기 SSR의 새 백엔드 요청은 캐시 미적중 시 최대 4회다. 기존 곧 끝나요·장소 섹션 요청은 유지한다.
- SSR payload를 사용해 Hydration 시 초기 브라우저 중복 요청을 하지 않는다.
- 국가 페이지 전환·스와이프·이미지 표시는 API를 호출하지 않는다. 지역 카드 선택, 조건 적용·삭제, 더 보기는 필요한 목록 1페이지만 요청한다. 캐시 적중 시 백엔드 재요청은 없다.
- 인증·쿠키를 전달하지 않는다. 허용된 고정 경로와 쿼리만 사용하며 임의 URL 프록시는 만들지 않는다.
- 오류는 빈 목록이나 0개로 바꾸지 않고 재시도를 제공한다. 더 보기 오류 시 기존 카드를 유지한다.

## 필터와 페이지네이션

- 지역 카드 클릭 시 실제 옵션에 해당 국가·ID가 있는지 확인한 뒤 전체 탭으로 이동한다. 국가+지역 필터를 적용하며 이전의 상충하는 필터는 초기화한다.
- 조건 시트의 지역·태그 목록도 실제 옵션 API를 사용한다. 국가 변경 시 다른 국가의 지역 선택을 제거한다.
- 필터 변경·삭제 시 누적 목록과 커서를 초기화한다. 진행 중인 추가 페이지 요청을 중단하고 오래된 응답이 새 결과에 섞이지 않게 한다.
- 더 보기는 서버 커서로 진행하며 중복 publicId를 제거한다. 반복 커서는 오류 처리한다.
- 첫 커서는 SSR 데이터에서 직접 계산해 초기 HTML에도 더 보기를 포함한다. SSR에서 실행되지 않는 비동기 watch에 첫 표시를 의존하지 않는다.
- 상세 링크는 기존 `/places/{publicId}`를 사용한다. 좋아요는 기존 준비 중 상태를 유지한다.

## 지역 레이아웃

- 한국/일본 총 2페이지, 각 4장과 하단 2개 인디케이터다. 기존 Embla를 사용하며 무한 반복하지 않는다.
- PC 1120px 이상은 4열·16px, 태블릿 768px 이상은 2열·16px, 모바일은 2열·8px이다.
- 카드 비율 1.6:1, radius 12px, 지역명은 왼쪽·하단 16px, 18px/700/흰색이다.
- 실제 승인 이미지가 연결되면 크기 지정·cover·lazy loading을 적용한다. 현재 이미지 URL은 null이며 404 요청이나 대체 외부 요청을 만들지 않는다.
- 모든 지역명은 SSR HTML에 포함한다. 비활성 국가 페이지는 inert 처리하며 인디케이터·좌우 키·모바일 스와이프로 전환한다.

## 검증 기록

실제 공개 API에서 8개 지역, 국가 KR/JP, 진행·예정·종료 상태, 복수 지역·태그 필터와 3페이지 중복 없음까지 확인했다. API 응답 캡처는 검증에만 사용하며 제품 데이터로 포함하지 않는다.

- 최종 `npm run typecheck`, `npm run build` 통과.
- 실제 응답을 재생한 Nitro SSR에서 실제 팝업 10장·지역명 8개·첫 더 보기가 초기 HTML에 포함됐다. Hydration의 초기 중복 API 요청은 0회였다.
- 같은 응답을 재생한 비표시 Chrome에서 8개 지역 클릭 후 국가·지역 ID 적용, 10→20→22개 더 보기, 필터 시트 적용·칩 삭제 시 페이지 초기화, 잘못된 쿼리 거부와 서버 캐시 재사용을 확인했다.
- PC 826px 콘텐츠에서 194.5px 카드 4열·간격 16px, 태블릿 2열·간격 16px, 모바일 2열·간격 8px 및 1.6:1 비율과 가로 넘침 없음을 확인했다.
- 국가 인디케이터와 모바일 스와이프 전환 시 API 요청이 추가되지 않았다. 최종 Hydration mismatch·미처리 예외는 없었다.
- 별도의 실제 운영 사진 다운로드나 스크린샷 촬영은 하지 않았다. 지역 이미지의 출처·권리 확인 및 승인 파일 반입은 남은 작업이다.

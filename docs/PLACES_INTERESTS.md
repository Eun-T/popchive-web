## 이미지

RN `assets/images/categories/`의 실제 WebP 4장은 존재하나 원본 출처·웹 공개/재배포 허가를 확인할 파일별 기록은 찾지 못했다. **이미지 복사 없음**. [이미지 반입 기록](../public/images/categories/README.md)에 확인할 파일과 항목을 정리했다.

현재 중립 회색 배경과 RN과 같은 방향의 어두운 가로 그라데이션을 사용한다. 흰색 카테고리명과 오른쪽 화살표는 이미지 없이도 보인다. 승인 이미지가 연결되면 지정 크기·cover·lazy loading을 적용하고 이미지 실패 시 같은 중립 배경으로 대체한다.

## UI 및 필터 연결

- 기존 주간 섹션 바로 아래 마지막 섹션으로 추가했다. 앞선 탐색 컴포넌트 4개는 수정하지 않았다.
- 제목은 다른 탐색 섹션과 같은 20px/700, 위 간격 40px이다. 설명은 요청 문구 그대로 14px 보조색을 사용한다.
- PC·태블릿은 2열·16px 간격·160px 높이, 모바일은 1열·140px 높이, radius 12px이다.
- 카테고리 구성은 `shared/utils/placeInterests.ts`의 정적 배열이다. 기존 `/api/places/options`에서 이미 확보한 태그 옵션을 props로 재사용하며 카드 표시용 API를 추가하지 않았다.
- ID와 실제 태그 이름이 일치하는 카드만 활성화한다. 확인되지 않은 태그로 이동하는 동작을 만들지 않는다.
- `usePlacesBrowse.selectCategory`는 기존 applied/draft 필터를 사용한다. 국가·지역·상태·다른 태그를 비우고 선택한 태그 한 개만 적용한다. RN의 국가 유지와 달리 웹에서는 요청한 충돌 방지를 위해 기존 지역 바로가기와 동일하게 새 조건으로 시작한다.
- 기존 목록 조회·정렬·커서·중복 제거·요청 취소·캐시를 그대로 사용한다. 필터 변경 시 기존 로직이 누적 페이지를 비워 첫 페이지부터 조회한다.
- 전체 탭 카드 디자인, 조건 설정 시트의 디자인, 기존 섹션 데이터 로직은 변경하지 않았다.

## URL·뒤로 가기·SSR

- 카테고리 진입 URL은 `/places?tab=all&tagId=1` 같은 형태다. 새로운 페이지나 필터 시스템을 만들지 않는다.
- 클릭 전 현재 탐색 위치를 `tab=explore`로 기록한 뒤 카테고리 URL을 push한다. Back은 탐색 탭으로, Forward는 카테고리 목록으로 돌아온다. 같은 페이지 생명주기에서는 진입 전 필터도 복원한다.
- 일반 탭 전환은 필요한 경우 해당 카테고리 URL을 정리한다. 지역 바로가기도 같은 최소 탭 전환 처리를 사용해 오래된 카테고리 URL과 충돌하지 않는다.
- 직접 카테고리 URL 진입 시 `usePlacesBrowse`의 초기 조건에 태그 ID를 전달해 기본 전체 목록을 먼저 요청하지 않는다.
- 카테고리 이름과 설명은 초기 HTML에 포함한다. 직접 URL 진입의 실제 목록도 SSR로 렌더링하고 payload를 재사용한다.

## 요청 및 검증

- 카드 표시 추가 요청 **0회**, 카테고리별 개수 요청 **0회**. 클릭 후 기존 전체 목록의 필요한 첫 페이지 1회만 요청한다. 기존 Nitro 페이지 캐시에 적중하면 백엔드 요청은 생략된다.
- 기존 태그 옵션 요청과 캐시를 재사용하며 새 백엔드/Nuxt API나 의존성을 추가하지 않았다.
- `npm run typecheck`, `npm run build` 통과.
- 실제 태그·팝업 공개 API 응답을 검증한 뒤 같은 응답을 재생하는 격리된 비표시 Chrome에서 네 카드 클릭, 국가·지역·상태 해제, 실제 태그 결과와 필터 칩·시트 선택 일치를 확인했다.
- PC·태블릿 2열·405×160px, 모바일 1열·140px 높이, 흰 글자, 12px radius, 텍스트 잘림·가로 넘침 없음을 확인했다.
- Back/Forward의 탭·필터 복원과 직접 카테고리 URL의 SSR·Hydration을 확인했다. 초기 Hydration 추가 API 요청 0회, 미처리 예외·Hydration mismatch 없음.
- 실제 이미지의 크롭 검증은 사용 권리 확인과 이미지 반입 후 가능하다. 이미지 파일은 복사하지 않았으며 외부 이미지 요청이나 스크린샷 촬영도 하지 않았다.

# GA4 도입 전 한국 서비스 개인정보 검토

검토일: 2026-10-27. 대상은 현재 한국 공개 웹이며 일본 서비스 출시를 가정하지 않는다. 이 문서는 도입 검토 기록이고, 공개 개인정보처리방침이나 운영자의 확정된 법적 판단을 대신하지 않는다.

## 결론

**한국 대상 웹에서 GA4를 사용한다는 사실만으로 최초 방문 동의 배너가 일률적으로 의무화되는 것은 아니다.** 다만 이것이 GA4의 모든 수집을 고지·거부 방식만으로 활성화해도 된다는 뜻은 아니다. 수집 정보의 식별 가능성, 처리 목적·근거, Google과의 처리 관계·국외 처리 조건을 확인해야 한다.

이번에는 배너·GA 태그·환경변수·기존 정책을 변경하지 않았다. 계정 설정과 처리 근거가 확인되기 전 GA4 수집을 활성화하지 않는다. 아직 설치되지 않은 상태이므로 별도 차단 스크립트도 추가하지 않았다.

## 프로젝트에서 확인한 사실

- app/·shared/·nuxt.config.ts·package.json에 기존 GA/gtag/GTM 설치 및 수집 코드가 없다. 배포 플랫폼에서 별도로 주입하는 태그나 실제 운영 페이지는 이번 조사로 확인하지 않았다.
- 웹 저장소의 app/·public/·docs/에서 공개 개인정보처리방침, 개인정보 페이지, 분석 동의 UI를 찾지 못했다. 외부에서 운영 중인 정책의 존재 여부는 미확인이다.
- 측정 ID `G-6BQP2JS6MK`만으로 Google Signals·광고 연결·데이터 공유·User-ID·보유기간·국외 처리 조건은 확인할 수 없다. GA 관리자에 접속하거나 설정을 변경하지 않았다.
- 기존 SEO에 운영/Preview 구분이 있으며 향후 분석의 개발·Preview 제외에 재사용할 수 있다. SSR에서 분석 태그를 실행할 필요는 없다.

## 배너 없는 도입 검토안 — 아직 미확정

1. 목적을 공개 페이지의 방문·페이지 조회 통계로 제한한다. 이름·이메일·회원 ID·User-ID·검색어·입력 내용·정확한 위치는 보내지 않는다. URL query/hash와 referrer에 개인정보가 포함될 가능성도 차단한다.
2. Google Signals, 맞춤 광고, 리마케팅, 광고용 사용자 데이터·개인화, Google Ads 연계 및 Google 목적의 데이터 공유를 사용하지 않는 방향으로 계정 설정을 확인한다. 코드의 광고 플래그만으로 계정 전체 설정이 바뀐다고 가정하지 않는다.
3. 쿠키·이벤트·보유기간을 실제 설정과 일치하게 공개한다. 보유기간은 운영자가 정하고 계정에 적용한 뒤 기록한다. 집계 보고서 보관과 사용자/이벤트 보관기간을 혼동하지 않는다.
4. 푸터의 작은 `분석 수집 설정` 링크에서 수집 거부·재허용을 제공하고 선택을 브라우저에 저장한다. 거부 시 해당 측정 ID 비활성화, 이후 태그 로딩·이벤트 차단 및 접근 가능한 GA 쿠키 제거를 처리한다. 이미 전송된 데이터가 로컬 거부로 소급 삭제되는 것은 아니다.
5. 위 제한을 적용하더라도 비개인정보 처리 또는 적법한 비동의 처리 근거와 해당되는 국외 처리 근거가 확인되어야 한다. 정책 고지와 거부 버튼만으로 근거 부족을 해결하지 않는다. 불확실하면 개인정보보호책임자 또는 한국 개인정보 법률 전문가의 확인 후 활성화한다.

## 사전 동의가 필요한 수집으로 결정되는 경우

개인정보 처리인데 적용 가능한 비동의 근거가 없거나 국외 이전의 근거를 동의로 삼아야 하는 경우, 동의 전에 gtag.js 로딩·분석 쿠키·이벤트를 차단한다. `analytics_storage=denied`만 설정해 Google 태그를 먼저 로드하는 Advanced Consent Mode는 비동의 신호 전송이 가능하므로 완전 차단과 구분한다. [Google Basic Consent Mode](https://developers.google.com/tag-platform/security/guides/consent?consentmode=basic)

필요한 UI 제안은 작은 비차단 하단 안내와 동등한 `거부`/`동의`, 상세 고지, 푸터의 변경·철회 진입점이다. 수집·이용 동의와 국외 이전의 별도 동의가 필요한 경우 이를 하나의 모호한 동의로 합치지 않는다. 목적·항목·보유기간·거부권 및 국외 이전 국가·시기/방법·수령자/연락처·목적/기간 등 해당 고지사항을 확정한 뒤 UI를 구현한다. 이 단계에서는 UI를 추가하지 않았다.

## 개인정보처리방침에 확인·추가할 내용

- GA4 사용 목적, 실제 수집 항목, 쿠키/유사 식별자의 사용과 유효기간, 보유·이용기간.
- Google의 역할과 정보 이용 방식 및 관련 설명 링크, 처리위탁/제공 관계와 해당되는 국외 처리 고지·법적 근거.
- 수집 거부·선택 변경 방법, 거부해도 공개 웹 기능을 이용할 수 있다는 설명, 개인정보 권리행사 및 문의 경로.
- 광고 기능·회원 데이터 결합 여부, 시행일·변경 공지. 실제 하지 않는 처리를 고지하거나 미확인 수령 국가·기간을 임의로 기입하지 않는다.

운영 중인 정책 원문과 관리자 설정을 확보한 뒤 변경안을 별도로 검토한다. 이 내부 문서를 공개 정책으로 게시하지 않는다. [개인정보위 2026년 작성지침 개정 안내](https://pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&nttId=12021)

## 후속 구현의 기술 조건

- ID는 `NUXT_PUBLIC_GA4_MEASUREMENT_ID`로 관리한다. 개발·Preview는 기본 비활성화하고 SSR·SEO·기존 화면과 백엔드·DB를 유지한다.
- 최초 접속과 SPA 전환에서 page_view 발행 주체를 하나로 정한다. 수동 이벤트 방식이라면 `send_page_view:false` 외에도 GA 관리자에서 Enhanced Measurement의 브라우저 이력 기반 페이지뷰를 꺼야 한다. 자동 수집 방식과 혼합하지 않는다. [Google page_view 문서](https://developers.google.com/analytics/devguides/collection/ga4/views)
- 수집 방식 확정 후 타입 검사·프로덕션 빌드와 최초/SPA/거부/철회/재방문 시나리오의 중복·차단 검증을 수행한다. 이번은 사전 조사이므로 이를 실행하거나 통과했다고 기록하지 않는다.
